# Signoff integrity

Use this reference when a JEV-supported workflow can deploy, delete, suppress, waive, ignore a required failure, or cross another final approval boundary.

## Threat model

The calling agent can often edit the question, state, option wording, selected excerpts, and files in its workspace. It could therefore omit adverse evidence, rewrite a failure, or prompt toward a preferred option. A high JEV probability does not cure that problem and must never count as approval.

The local audit log records exactly what was submitted and returned. Its hash chain exposes accidental edits and simple partial modification, but a process with the same user permissions can rewrite the entire log and recompute the chain. Keep the authorization key, trusted evidence, and final enforcement outside that permission boundary.

## Required authorization record

Have the external authority issue a signed record equivalent to:

```json
{
  "schema_version": 1,
  "audit_id": "UUID from _jev_client",
  "request_sha256": "hex SHA-256",
  "response_sha256": "hex SHA-256",
  "evidence": [
    {"path": "logical/source/name", "sha256": "hex SHA-256"}
  ],
  "disposition": "approve",
  "scope": "release:service-a:2026-10-11",
  "reason": "required for waive; recommended for approve",
  "approver_id": "stable identity",
  "authority": "release-approvers",
  "issued_at": "RFC3339 timestamp",
  "expires_at": "RFC3339 timestamp or null",
  "signature": "provider-defined detached or envelope signature"
}
```

Allow only `approve`, `waive`, or `reject`. Require a reason and narrow scope for `waive`. Prefer short expiry for time-sensitive operations.

## Verification order

The host gate, not the agent, must:

1. Verify the signature with a key unavailable to the agent.
2. Resolve `approver_id` to an active identity with authority for the declared scope.
3. Require an allowed disposition and enforce waiver-specific policy.
4. Match `audit_id`, request hash, response hash, and evidence hashes byte-for-byte.
5. Reject expired, replayed, broader-than-requested, or already-consumed records.
6. Re-run deterministic gates or consume their trusted CI attestations.
7. Record the authorization and action in the system audit trail.

Never accept a signoff file merely because it exists in the workspace. Presence is not authenticity.

## Evidence producers

Prefer evidence generated by CI, policy engines, scanners, or other services whose output the agent cannot overwrite. If workspace files must be used, have the trusted workflow hash or attest them after the agent has finished editing and bind those hashes into the authorization record.

## Low-impact routing

Routine reversible classification may be auto-routed only when an external host policy explicitly permits it. That standing policy is the authorization boundary; the JEV response is still only a policy input. Any exception to deterministic requirements needs a fresh `waive` record.
